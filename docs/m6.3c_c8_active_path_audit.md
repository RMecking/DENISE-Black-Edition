## Active production call graph

For `MODE=1` and `L>0`, `physics_SH()` correctly dispatches to
`FWI_SH_visc()`. The active base evaluation then follows:

```text
physics_SH
  -> FWI_SH_visc
     -> grad_obj_sh
        -> sh(mode=0)              elastic base forward
        -> calc_res_SH
        -> sh(mode=1)              elastic nominal adjoint
        -> assemble_gradSH_exact   elastic Vs/rho assembly
     -> ass_gradSH_visc            legacy material conversion
```

The trial evaluation follows a different graph:

```text
step_length_est_sh
  -> calc_mat_change_test_SH_visc  updates u and rho only
  -> obj_sh
     -> matcopy_elastic_SH          no tau halo refresh
     -> prepare_update_s_visc_SH
     -> sh_visc(mode=2)             viscoelastic trial forward
```

Thus the top-level dispatch and trial propagator are viscoelastic, but the
active base objective and gradient are elastic. For nontrivial attenuation,
`J_base` and the zero-step trial cannot represent the same discrete forward
operator.

## Material and optimizer connectivity

`readmod_visc_SH()` reads physical Q from `.qs` but immediately stores
`q_to_tau(Q, mapping)` in `matSH.ptaus`. `matSH` has no separate owned-Q
array. Consequently a trial or accepted model cannot rederive tau from an
updated physical Q.

| Parameter class | Active gradient producer | Optimizer/storage | Trial update | Audit status |

The locked C7 output is a raw derivative of the verified discrete objective.

whether each array is a raw gradient or a descent direction. The present
method-dependent negations and the absent Q path do not support a stronger
sign claim.

## Minimal C8b design

C8b is limited to connecting the exact base objective and gradient. Its
predeclared production scope is:

```text
include/fd.h
src/Makefile
src/SH/alloc_matSH.c
src/SH/readmod_visc_SH.c
src/SH/FWI_SH_visc.c
src/SH/grad_obj_sh_visc_exact.c
```

The minimal design is:

1. Retain an owned physical-Q model array in `matSH` in addition to derived
   cell-centred and staggered tau.
2. Read Q into that owned array and derive tau through the selected locked
   legacy or physical-Q mapping.
3. Add one exact viscoelastic base objective/gradient driver. It must run the
   real `sh_visc` forward with the C7a observable trajectory, form the locked
   chronological receiver cotangent, and invoke the locked C5/C7 reverse-time
   material-gradient chain.
4. Return raw physical Vs/mu, rho, and Q derivatives once. The active driver
   must not additionally call `assemble_gradSH_exact()` or
   `ass_gradSH_visc()` on those results.
5. Freeze the optimizer-facing sign and parameter-class contract with focused
   tests before allowing those arrays to reach PCG or LBFGS.

C8b must prove that the base objective is viscoelastic, the locked C7 driver
is reachable, and the Q gradient reaches the declared optimizer boundary. It
does not yet repair line-search or accepted-model updates.
