# M6.3a viscoelastic SH FWI and attenuation-inversion audit

## Scope and evidence boundary

This document audits the current viscoelastic isotropic SH FWI path without
changing production code.  The audited Black Edition baseline is
`modernization` at
`0a79bd3b7198aca4ccb5819631a1a9bf7bd5f169`.  The historical comparison is
DENISE-SH at `9a4efe1db13c2076580cb36b4fc3a9c63a664079`.

DENISE-SH is used only as a genealogy and architecture reference.  Its
formulas and numerical behavior are not an oracle.  Any repair must be derived
from the current Black Edition discrete GSLS update and verified independently.

The classifications used below are:

- **VERIFIED**: a repository test directly supports the stated behavior;
- **WIRED**: the normal production call chain reaches the implementation;
- **EXISTS**: source/data structures exist but normal end-to-end use is not
  established;
- **INCOMPLETE**: pieces are reachable or relevant, but the end-to-end contract
  is broken, inconsistent, or unverified;
- **ABSENT**: no implementation of the required stage was found.

These labels apply to the exact capability named in each row.  In particular,
forward viscoelastic verification is not attenuation-gradient verification.

## Executive verdict

The current Black Edition does **not** provide a production-ready
viscoelastic SH attenuation/Q inversion.  The normal `MODE=1`, `L>0` driver is
reachable, but its principal objective/gradient call invokes the elastic
`grad_obj_sh()` routine, not `grad_obj_sh_visc()`.  The resulting forward and
adjoint runs use `sh()`, while line-search trials with `L>0` use `sh_visc()`.
The base and trial objective paths therefore implement different physics.

Even the unused `grad_obj_sh_visc()` path does not accumulate an attenuation
gradient.  Production `sh_visc()` stores no memory-variable history, forms no
`waveconv_ts_shot`, and uses the same dissipative GSLS recurrence during its
nominal adjoint run.  The required transpose recurrence is absent.

The repository contains attenuation-named arrays and partial three-parameter
optimizer helpers, but the production material-change routine never updates
`ptaus`, never applies Q/tau bounds, and never writes a physical-Q model.  No
Q-to-tau chain rule is applied.  This is an **INCOMPLETE legacy capability**,
not a verified inversion feature.

## Active Black Edition call chain

### Dispatch and model preparation

The active global dispatch is:

```text
denise -> physics_SH
  MODE=0 -> FD_SH
  MODE=1, L=0 -> FWI_SH
  MODE=1, L>0 -> FWI_SH_visc
```

For `MODE=1`, `L>0`, `FWI_SH_visc.c`:

1. allocates `waveSH`, `matSH`, and `fwiSH` state;
2. reads `.vs`/`.mu`, `.rho`, and `.qs` with `readmod_visc_SH()`;
3. maps external Qs to the internal scalar `ptaus` field;
4. exchanges `rho`, material, and `ptaus` halos with `matcopy_SH()`;
5. constructs staggered `mu` and tau fields with `av_mu_SH()` and `av_tau()`;
6. constructs the GSLS coefficients with `prepare_update_s_visc_SH()`; and
7. enters its iteration loop.

At each iteration the same halo, averaging, and coefficient preparation is
repeated before the objective/gradient calculation.

### Normal objective/gradient path

The active iteration contains this mismatch:

```text
FWI_SH_visc
  -> grad_obj_sh                 # elastic routine
       -> sh(..., mode=0)        # elastic forward
       -> calc_res_SH
       -> sh(..., mode=1)        # elastic adjoint
       -> assemble_gradSH_exact  # verified elastic Vs/rho assembly
  -> ass_gradSH_visc             # legacy transform applied afterwards
  -> PCG or LBFGS helpers
  -> step_length_est_sh
       -> calc_mat_change_test_SH_visc  # changes only Vs/rho
       -> obj_sh
            -> prepare_update_s_visc_SH
            -> sh_visc(..., mode=2)     # viscoelastic trial objective
  -> calc_mat_change_test_SH_visc       # final change, still only Vs/rho
```

Consequences:

- the reported `L2t[1]` is obtained from elastic synthetics;
- line-search `L2t[2]`/`L2t[3]` values are obtained from viscoelastic
  synthetics with fixed `ptaus`;
- for the supported `INVMAT1=1` path, the exact elastic physical Vs/rho shot
  gradient is then passed through the legacy `ass_gradSH_visc()`
  transformation, which does not contain the M5.1 exact-path bypass;
- the direction is not the derivative of the objective used by the line
  search; and
- no attenuation direction reaches the line search or final update.

This is a concrete active-path defect, independent of whether attenuation
inversion is requested.

|---|---|---|---|
| `0` | physical shot sources, `ADJ_SIGN=+1`; complete velocity, GSLS stress/memory, CPML, MPI and optional free-surface stepping | stores `pvzp1`, `uzx`, and `uz` at `DTINV` samples when global `MODE` is 1 or 2 | viscoelastic forward stepping is **VERIFIED** in forward tests; attenuation-gradient state storage is **ABSENT** |
| `1` | reversed receiver residuals, `ADJ_SIGN=-1`; calls the same `update_v_PML_SH()` and same forward GSLS stress/memory recurrence | correlates only density and legacy GF2 material terms | nominal adjoint path **WIRED**, discrete viscoelastic adjoint **INCOMPLETE** |
| `2` | physical sources, `ADJ_SIGN=+1`; no forward-state storage | produces line-search synthetics only | viscoelastic trial forward **WIRED**; attenuation trial update **ABSENT** |

`update_s_visc_PML_SH()` accepts `mode` and `fwiSH` arguments but does not use
either.  `sh_visc()` passes `exact_elastic_sh_adjoint=0` to
`update_v_PML_SH()`, so the receiver-metric correction verified for the exact
elastic SH adjoint is not selected in this path.

The M6.2 free-surface calls are reached for all three modes when
`FREE_SURF && POS[2]==0`.  That proves shared forward boundary execution, not
that applying the same helpers in a nominal adjoint run is their algebraic
transpose.

## Current GSLS recurrence and independent derivative

The following derivation is based on `prepare_update_s_visc_SH.c` and
`update_s_visc_PML_SH.c`, not on DENISE-SH.

For one staggered stress component and one spatial strain-rate sample `e`, let
`tau` be the relevant internal relaxation-strength field, `M` the staggered
unrelaxed shear modulus, and

```text
S       = sum_l (omega_s^2 theta_l^2)/(1 + omega_s^2 theta_l^2)
m(tau)  = M/(1 + S tau)
F(tau)  = DT m(tau) (1 + L tau)
D_l(tau)= m(tau) eta_l tau
b_l     = 1/(1 + eta_l/2)
c_l     = 1 - eta_l/2
A_l     = b_l c_l
C_l(tau)= -b_l D_l(tau)
h        = DT/2
```

The implemented local state map is

```text
r_l^{n+1} = A_l r_l^n + C_l(tau) e^n
s^{n+1}   = s^n + F(tau)e^n
                  + h sum_l (r_l^n + r_l^{n+1}).
```

With fixed relaxation frequencies, `eta_l`, `b_l`, `c_l`, and `A_l` do not
depend on `tau`.  The required coefficient derivatives are

```text
m'(tau)   = -M S/(1 + S tau)^2
F'(tau)   = DT [m'(tau)(1 + L tau) + L m(tau)]
D'_l(tau) = eta_l [m'(tau) tau + m(tau)]
C'_l(tau) = -b_l D'_l(tau).
```

For a reverse step with incoming adjoints `bar_s^{n+1}` and
`bar_r_l^{n+1}`, define

```text
t_l = bar_r_l^{n+1} + h bar_s^{n+1}.
```

The exact local transpose contributions are then

```text
bar_s^n   += bar_s^{n+1}
bar_r_l^n += A_l t_l + h bar_s^{n+1}
bar_e^n   += F(tau) bar_s^{n+1} + sum_l C_l(tau) t_l
g_tau     += e^n [F'(tau) bar_s^{n+1}
                  + sum_l C'_l(tau) t_l].
```

This recurrence requires an adjoint memory state per mechanism.  Re-running
the dissipative forward recurrence with residual sources is not this
transpose.

For the `sxz` branch, the current coefficient uses `ptausipjp`, produced by
the four-cell arithmetic average

```text
tau_ipjp[j,i] = 0.25 (tau[j,i] + tau[j,i+1]
                             + tau[j+1,i] + tau[j+1,i+1]).
```

Consequently, an edge-level `g_tau_ipjp` must be scattered by the exact
transpose of that average (one quarter to each participating cell).  The
`syz` branch uses the cell `ptaus` field directly.  This staggered transpose,
including MPI seam halos, is absent from the current attenuation path.

The full discrete adjoint must additionally reverse, in exact opposite order,
the velocity update, stress/memory update, CPML states, MPI exchanges, source
and receiver injection, and free-surface completion.  The equations above are
the local GSLS material block only; they are not by themselves a complete
production gradient.

## Q-to-tau parameter semantics

`readmod_visc_SH()` maps external Qs to one internal scalar tau per cell.
For the two supported forward-input modes:

```text
legacy:       tau(Q) = 2/Q
physical-Q:   tau(Q) = 1/(a Q + b)
```

where `a=q_mapping.inverse_tau_per_q` and
`b=q_mapping.inverse_tau_offset` are fixed by the chosen relaxation
frequencies and approximation band.  The missing chain rules are therefore

```text
legacy:       d tau/dQ = -2/Q^2
physical-Q:   d tau/dQ = -a/(a Q + b)^2 = -a tau^2
g_Q = g_tau (d tau/dQ).
```

For staggered coefficients the correct order is: form edge `g_tau`, apply the
transpose of `av_tau()` to obtain cell `g_tau`, then apply `d tau/dQ` at the
cell.  Applying Q bounds directly to tau, or treating an averaged tau as a Q,
would be dimensionally and mathematically wrong.

A repair must choose and document one user-facing optimization variable.  The
preferred contract is physical Qs: store/update/bound/write Qs, then recompute
tau through the selected mapping for every trial and accepted model.  If an
internal-tau optimizer is retained, the inverse mapping and transformed bounds
must be explicit, and outputs must not be mislabeled as Qs.

## Concrete defects and gaps

1. **M63-ACTIVE-PHYSICS-SPLIT**: `FWI_SH_visc()` uses elastic
   `grad_obj_sh()` for the base objective/gradient but viscoelastic `obj_sh()`
   for trial objectives.
2. **M63-DOUBLE-LEGACY-ASSEMBLY**: for `INVMAT1=1`, the exact elastic gradient
   returned through `grad_obj_sh()` is subsequently transformed by
   `ass_gradSH_visc()`, which lacks the M5.1 exact-path bypass.
3. **M63-VISCO-ADJOINT-ABSENT**: nominal mode 1 reuses the forward GSLS
   recurrence and has no adjoint memory state or transpose recurrence.
4. **M63-RECEIVER-METRIC**: the viscoelastic call explicitly disables the
   exact elastic receiver metric.
5. **M63-TAU-GRADIENT-DISCONNECTED**: attenuation fields are allocated and
   initialized, but no production forward history, adjoint correlation, shot
   sum, or activation exists.
6. **M63-DTINV-QUADRATURE**: the legacy visco assembly lacks the established
   temporal quadrature factor; attenuation quadrature is entirely absent.
7. **M63-TAU-STAGGERED-VJP**: no transpose of the four-cell tau averaging or
   MPI seam accumulation exists.
8. **M63-PCG-THIRD-CLASS**: vectors are sized for three classes while the
   helpers fill/extract only two, leaving the attenuation segment without a
   defined contract.
9. **M63-LBFGS-TAU-SCALING**: third-parameter file/vector code exists, but
   active `C_taus` initialization and valid gradient/update semantics do not.
10. **M63-NO-MODEL-UPDATE**: production trial/final updates, Q/tau bounds, and
    reusable attenuation output are absent.  `ptaus_old` is not copied by the
    production step-length helper.
11. **M63-NO-Q-CHAIN**: neither legacy nor physical-Q input mapping is
    differentiated back to Qs.
12. **M63-FD-DIAGNOSTIC-NOT-ORACLE**: `FD_grad_SH.c` contains a tau branch, but
    `FD_GRAD_MAT` is hard-coded to density, the tau branch is not covered, and
    it is not an independently locked production Taylor oracle.

## Required independent frozen RED oracles before repair

M6.3b should freeze failures without modifying production code.

1. **Active-path provenance oracle**: record the exact forward/adjoint/line
   search functions and executable SHA.  Demonstrate that base and trial
   objective physics currently differ.
2. **Local GSLS tangent/transpose oracle**: implement the recurrence above in
   independent test code and require machine-precision dot-product closure for
   random multi-mechanism states and tau values.  Test coefficient derivatives
   against centered finite differences.
3. **Global viscoelastic SH adjoint dot-product oracle**: require discrete
   dot-product closure for the complete state mapping used by the target
   gradient.  This must cover the velocity update, GSLS stress and memory
   update, CPML state updates, MPI exchanges and their transposes, and the
   receiver/source injection metric.  Exercise both `FREE_SURF=0` and the M6.2
   `FREE_SURF=1` boundary.  Component-level checks may additionally isolate a
   failure, but the full composed operator must close.  The local GSLS oracle
   remains a localization test and does not replace this global acceptance
   gate.
4. **Q mapping chain-rule oracle**: verify `d tau/dQ` analytically and by finite
   difference for legacy and physical-Q modes, including L=1 and L=4.
5. **Staggered tau VJP oracle**: verify the transpose of `av_tau()` on a
   heterogeneous field, including contributions at 2x1 and 1x2 MPI seams.
6. **Production objective oracle**: use one immutable observed data set and
   identical model files for all perturbations.  Record hashes of Q/tau, Vs,
   rho, observed data, and synthetics.
7. **Five-point directional derivatives**: independently perturb tau first,
   then physical Qs, with a fixed epsilon ladder and raw `J(+-h)`/`J(+-2h)`.
   Require no fitted sign or scale.  Include homogeneous, heterogeneous, and
   held-out models.
8. **Temporal oracle**: compare DTINV 1/2/3/4 with identical forward
   objectives.  Separate forward/objective invariance from gradient
   quadrature error.
9. **Boundary oracle**: run the same derivative at `FREE_SURF=0` and the M6.2
   flat `FREE_SURF=1` geometry.  Treat M6.2 only as forward evidence.
10. **MPI oracle**: require 1x1/2x1/1x2 gradient and directional-product
   closure, with explicit seam residuals.
11. **Optimizer/update contract oracle**: after the gradient is repaired,
     require PCG and LBFGS to round-trip exactly three initialized parameter
     classes, enforce Q-space bounds, reduce the same objective in line search,
     accept a nonzero Q update, write physical Qs, and restart with identical
     tau and synthetics.
12. **Protected paths**: retain all M4.2/M6.2 forward results, elastic M5/M6.1
     gradients, high-Q convergence, `L=4`, CPML, and MPI decomposition checks.

The initial RED baseline should assert the concrete mismatches rather than
XFAIL an entire integration function.  Crashes, missing outputs, nonfinite
values, provenance failures, or MPI hangs must remain ordinary failures.

## Proposed milestone split

- **M6.3a -- audit/design (this document):** source call-chain, independent
  discrete recurrence derivative, parameter semantics, cross-code genealogy,
  and frozen-oracle design.  No production changes.
- **M6.3b -- frozen RED oracle:** independent local GSLS transpose tests, the
  global viscoelastic SH adjoint dot-product test, and production tau/Q finite
  differences, DTINV, MPI, free-surface and provenance baselines.  Preserve the
  failing production state for review.
- **M6.3c -- complete discrete objective/adjoint/gradient repair:** make base,
  adjoint and trial paths use one viscoelastic objective and repair every
  state/operator transpose required by the target gradient, including the
  memory state, receiver metric, staggered tau VJP, temporal quadrature and Q
  chain rule.  M6.3c is complete only when the full discrete viscoelastic SH
  objective/adjoint/gradient path satisfies all frozen M6.3b oracles.  Existing
  elastic or viscoelastic spatial, CPML, MPI and free-surface operations may be
  reused only where existing or new evidence establishes the transpose/adjoint
  property required by this path.  Do not yet claim optimizer convergence.
- **M6.3d -- parameter/update completion:** define the physical-Q optimizer
  contract, complete PCG/LBFGS third-class storage, Q bounds, line search,
  accepted model write/reuse, and successful optimizer smokes.

Keeping gradient correctness separate from optimizer/update completion avoids
using a changing line search to validate the derivative that drives it.
